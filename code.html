Code the thread, then read it closely

Users — fact-checkers, community notes and commenters — disagree around competing statements: expressions of an attitude, belief or opinion. In this step you write, for every comment of your CSV, the statement it makes.

In the Tucker Carlson interview thread, at least eighteen statements can be told apart, among them: 4. Western populations are misinformed by their media, which tend to ignore Russian opinions. 12. Western media has never suppressed Russian or Putin's viewpoints (contradicts 4). 15. What Tucker expresses is an opinion and does not need to be verified. The fact-checker and the commenters are not disagreeing about what happened in the interview, but about what journalism is for.

A. Write your codebook

  1. Start from the Datasets, or from scratch. If you downloaded your thread with statements, the Statement column already holds the statements the Datasets distilled: list the distinct ones, and check them against the comments. Keep, merge, split or reword them. Otherwise read the post, the fact-check, the notes and some fifty replies, and write down each new statement you meet; stop when new comments stop producing new statements.
  2. Aim for 10 to 25 statements. Give each a number and one sentence. Add what counts as making it and what does not.
  3. Keep the subject apart from the process. "The video is from 2016" is about the post; "this needs no note" is about classifying it. Both can be statements, but not the same one.

B. Code your CSV

  1. Open the CSV in a spreadsheet. Google Sheets: File → Import. Excel: Data → From Text/CSV, with UTF-8 as the file origin (a plain double-click can garble accents and emoji).
  2. Fill the Statement column. For each row, write the statement it makes: its number from your codebook (3) or its exact wording. If a row makes several, separate them with a vertical bar: 3 | 7. If it makes none — a joke, an insult, something off-topic — leave the cell empty.
  3. Code the original post and the fact-check too. Bridge uses them to tell which statements belong to which side.
  4. Optional: add a Context column with yes for comments that explain, contextualise or give a source for a statement (theirs or someone else's), and no otherwise. Bridge's Context option uses it.
  5. Code in pairs, at first. Two of you code the same 30 rows without looking at each other's codes, then compare. Where you disagree, the statement is badly defined: reword it in the codebook and code again.
  6. Save as CSV (UTF-8), and leave the other columns as they are.

If you will use an LLM in the next step, code at least 20 to 30 rows by hand first: they are what you will check the model against.

C. Read the thread closely

With the statements coded, read the thread again, statement by statement, and answer:

  1. What is the majority opinion? Which statements do most comments make, and which kinds of users make them: the post, the fact-checker, the notes, the replies?
  2. What is the minority opinion? Which statements do few comments make? Are they few because they are marginal, or because the thread drowns them out?
  3. Where do users misunderstand one another? For instance, reading the other side's normative statement ("this should not be platformed") as a factual one ("this is false"), or the reverse.
  4. Where do they misrepresent one another? Attributing to the other side a position it does not hold.
  5. What does each side ignore? Statements of the other side that get no reply at all.
  6. What premise would both sides need to share to be arguing about the same thing — and do they share it?

For every answer, keep two or three quotes with their sample_id or url: they are your evidence. Bridge shows the share of comments that make each statement, which helps with the first two questions.
